# 引脚分配（v4：OLED I2C + 4x4 矩阵键盘，已在面包板实测通过）

v4 的分配是**实测逼出来的**，不是纸上分配。核心约束一句话：

> ESP32-C3 SuperMini 在三个 strapping 脚 **GPIO2 / GPIO8 / GPIO9** 上带板载上拉，
> 强到芯片内部 45kΩ 下拉压不住，因此这三个脚**只能当输出，不能当任何需要判读电平的输入**。

剩下 8 个干净引脚（GPIO0/1/3/6/7/10/20/21）正好等于 4×4 矩阵需要的 8 根线，
三个脏引脚正好等于三个 LED。刚好用满，没有余量。

一体板拆解：左侧 OLED 走标准 I2C（VCC/GND/SCL/SDA），右侧 4×4=16 键是**裸矩阵输出**
（R1-4 行 + C1-4 列，共 8 根线，不带 I2C 转换芯片）。

## 引脚可用性实测

把除 I2C 外的引脚全部设为 `INPUT_PULLDOWN` 并显式 `gpio_pullup_dis()`，逐个读电平：

```
GPIO   0=0  1=0  2=1  3=0  6=0  7=0  8=1  9=1  10=0  20=0  21=0
                   ^                    ^    ^
              被板载上拉顶着，只能当输出
```

被顶高的正好是三个 strapping 脚。验证方法：拔掉该脚**所有**外部接线后重测，仍读到 1，
说明上拉在 SuperMini PCB 上，不是接线问题，也不是芯片内部那个可以关掉的上拉。

## 为什么 GPIO2 不能当矩阵行

这个坑的表现极具误导性，值得记下来：

GPIO2 被板载上拉顶着，纯 `INPUT` 时是 3.3V；加内部 45kΩ 下拉后降到约 2.7V；
按下该行某个键后，列脚自带的 45kΩ 下拉并进来，节点降到约 **2.3V** —— 正好压在
VIH（0.75×3.3 = 2.48V）边缘的不确定带里。于是：

- GPIO6 / GPIO7 把 2.3V 判成**低** → C1、C2 表现正常
- GPIO10 / GPIO20 把 2.3V 判成**高** → C3、C4 整列误报

症状是"第三排只有后面两个键出错"，看起来像键位映射错误或两个独立故障，
实际上全程是同一个上拉。**边界电压故障会伪装成"只修好了一半"** —— 遇到
"只有部分引脚有问题"时，先量电平、怀疑不确定带，不要先怀疑映射。

另一个教训：不要用 `analogRead` 去量同一个引脚的数字上下拉状态。ADC 模式本身会
关掉上下拉，测量会破坏被测状态（曾据此读到 2912mV 并误以为是铁证）。

## 矩阵扫描原理

扫描某行时：该行 `OUTPUT` 拉高，**其余三行 `INPUT_PULLDOWN`**，列脚 `INPUT_PULLDOWN`，
切换后等 50µs 再读（杜邦线寄生电容比 PCB 大）。

两个都不能用的做法：

- **其余行 `OUTPUT` 拉低** —— 同一列上两个不同行的键同时按下时，被拉高的行经键1→列→键2→
  被拉低的行，形成推挽对推挽直接短路，只靠 GPIO 驱动能力限流
- **其余行纯 `INPUT`（高阻）** —— 引脚若带上拉就会悬空成高，把高电平灌进列线造成整列误报

`INPUT_PULLDOWN` 同时满足两个要求：有确定电平，且足够弱（45kΩ），
被扫描行往它灌的电流只有约 73µA。

## 固件自检

`firmware/tools/matrix_probe` 上电会做两项自检，这类问题上电即可见：

```
[selftest] 四个行脚纯 INPUT 时均为低        # 有引脚悬空为高会点名报出
[selftest] 空闲电平正常：C1~C4 全部为低      # 列脚为高说明接到了电源轨或行线
```

## LED0 为什么必须反接

GPIO9 是 boot 模式选择脚，内部只有 45kΩ 上拉，[esptool 文档](https://docs.espressif.com/projects/esptool/en/latest/esp32c3/advanced-topics/boot-mode-selection.html)
说明要进下载模式需要 10kΩ 级的强下拉。若正接（GPIO9 → 330Ω → LED → GND），
这条 DC 通路会把 GPIO9 压到约 1.7V，落在 VIL(0.83V)/VIH(2.48V) 之间的不确定带，
可能被判成低而进入下载模式，表现为**时好时坏的启动失败**。

反接（3V3 → 330Ω → 阳极，阴极 → GPIO9，低电平亮）后 GPIO9 被拉向 3V3，稳定为高。
代价是固件里 LED0 逻辑取反。

LED1 放在 GPIO2 上没有这个问题：作**输出**时板载上拉无害，而且上电即为高，
对 strapping 反而有利。

## 键位映射

`R?C?` 与物理位置一一对应（行 1→4 为上→下，列 1→4 为左→右），已实测确认：

|---|---|---|---|---|
| **R1** | 1 | 2 | 3 | A |
| **R2** | 4 | 5 | 6 | B |
| **R3** | 7 | 8 | 9 | C |
| **R4** | * | 0 | # | D |

## 变更历史

- v1：ST7735 SPI 彩屏 + 5 个独立按键模块（GPIO0/1/5/10/21），LED1 反接在 GPIO9
- v2：改用 4P I2C 接口键盘的构想（后确认该键盘实为矩阵输出，非真 I2C，方案作废）
- v3：OLED 走 I2C（GPIO4/5），16 键矩阵接 GPIO0/1/2/3 + GPIO6/7/10/20，LED0 占 GPIO9、LED1 占 GPIO21
- **v4（当前，面包板实测通过）**：矩阵 R3 从 GPIO2 移到 **GPIO21**，LED1 从 GPIO21 移到 **GPIO2**。
  原因是 GPIO2 带板载上拉不能当输入。
  载板原理图 `hardware/kiboard/kiboard.kicad_sch` **已同步到 v4**，ERC 0 error / 1 warning。

  原理图侧只改了 6 处网络标签、元件一个都没动：J1-GPIO2 与 J4-R3 换名、
  J2-GPIO21 与 R2 顶端换名、R1 顶端 `GPIO9_LED0`→`3V3`、D1 阴极 `GND`→`GPIO9_LED0`。
  最后两处就是 LED0 的反接——**阳极始终在电阻那一侧，所以只换标签极性天然是对的**，
  不需要翻转 D1。

  ERC 查不出 v3 的问题（它不知道板载上拉），所以另加了
  `hardware/check_netlist.py`：拿导出的 netlist 对固件的 `ROW_PINS`/`COL_PINS`/`leds[]`，
  逐条核矩阵 8 线、LED 极性与有效电平、I2C。打板前跑一次，退出码非 0 就是分叉了。

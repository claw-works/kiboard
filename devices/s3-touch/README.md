# 方案 B：ESP32-S3 触摸屏（未开始）

ESP32-S3 + 触摸屏，界面上做软键盘。**目录先占位，代码还没写。**

## 为什么排在手机 App 之后

不是技术难度问题，是验证顺序问题：这个方案要等 PCB，而
[`../mobile/`](../mobile/) 不用等硬件就能验证协议抽象对不对。等协议稳了再做硬件，
可以一次做对，不用因为协议返工重新打板。

## 为什么要 S3 而不是继续用 C3

C3 撑不起触摸屏，三个硬伤：

- **没有并口 LCD 外设**。S3 有 LCD_CAM（i8080 8/16 位、RGB），C3 只能软件翻 GPIO
- **引脚不够**。C3 SuperMini 只有 11 个可用 GPIO，其中 3 个还只能当输出
- **内存不够**。480×320 的 16bpp 全屏帧缓冲是 300KB，C3 总共 400KB SRAM，放不下全屏 sprite

S3 顺带解开的：双核（渲染和按键扫描互不阻塞）、可配 PSRAM（放得下帧缓冲）。

## 待决问题

**这些必须在动手前定，不然会返工：**

- **屏幕与驱动选型**。ST7796 / ILI9488 这类 320×480 都可选，但**必须买 SPI 或并口
  breakout，不要买 Mega2560 shield 版**——那是 Arduino 排针 + 8/16 位并口，插不上也不划算
- **PSRAM 类型**。八线（OPI）PSRAM 的模块会占掉 GPIO33~37，四线（QSPI）不占。
  引脚规划前先确定买的是哪种，否则规划全废
- **strapping 脚**。S3 是 GPIO0/3/45/46，其中 GPIO45 还影响 VDD_SPI 电压，接错能烧
  PSRAM/flash。GPIO19/20 是 USB
- **强确认怎么做**。物理键的"按住 900ms"在触摸屏上不能照搬：触摸面没有触觉反馈，
  也没有固定位置的肌肉记忆，而且"接受"按钮可以被界面重排。需要设计一个等价强度的手势
  并说明为什么等价，见 [`../../docs/threat-model.md`](../../docs/threat-model.md)
- **要不要做 USB HID**。S3 有原生 USB-OTG，技术上能当键盘。**建议不做**：一个自制的、
  能注入按键的 USB 设备在装了 EDR 的机器上就是 BadUSB 的形状，而 kiboard 根本不需要
  HID——审批走的是 hub 的 HTTP，设备不用假装键盘

## 协议侧的要求

这个方案是**自渲染设备**：`hello` 里声明 `render: "self"`，hub 只发结构化数据，
排版全在设备上。

因此要自己遵守 [`../../protocol/README.md`](../../protocol/README.md) 里
required-to-display 的约束——尤其是逐字原文必须显示，不能只显示模型自己写的 summary。
界面漂亮优先的实现最容易在这里出错。
